# 校园去中心化带宽分享激励系统 (MVP) 论文写作参考文档

本文档整理了当前带宽分享系统的核心理论、实现思路、功能特性及演示操作流程，可直接作为你们撰写论文（如系统架构、博弈论机制设计、激励模型等章节）的参考素材。

## 1. 核心方法与模型 (Methods & Models)

本系统旨在解决去中心化 P2P 网络或 6G 边缘计算网络中常见的 **“公地悲剧” (Tragedy of the Commons)** 问题，即用户倾向于白嫖网络资源而不愿贡献自己的带宽。为此，系统引入了以下核心模型：

### 1.1 基于博弈论的激励与惩罚模型 (Game Theory-based Incentive Model)
*   **合作博弈 (Cooperative Game)**：鼓励节点将闲置带宽共享。系统设定了清晰的连通性红利（每日挂机基建奖励）和具体的流量分发报酬。
*   **“搭便车”零容忍机制 (Anti-Freerider Mechanism)**：对于只下不传的“搭便车者”，系统采用严厉的惩罚策略。一旦查实存在违规白嫖流量（`freerideGb`），将在每日结算时扣除高额积分，进行声誉降级，并强制实施网络阻断/限速（如降至 2Mbps）。

### 1.2 通缩型/通缩倾向的经济学模型 (Deflationary Economic Model)
*   为了防止系统内积分（Credits）无限通胀导致其丧失激励价值，系统设计了**不守恒/微通缩的兑换池**。
*   **消费与收益剪刀差**：消费者每消耗 1GB 流量，需支付 6.00 积分（`COST_PER_GB`）；而全网奖金池仅释放 5.00 积分（`REWARD_POOL_PER_GB`）。系统中央银行自动回收 1.00 积分差额，确保积分池紧缩，提升积分购买力。
*   **基建闲置税 (Idle Tax)**：针对既不消费也不分享的“摇摆潜水者”，系统每日征收其余额 1% 的闲置税。这迫使“死号”和屯币者必须开启分享，否则资产将不断缩水。

### 1.3 基于声誉的分红调度算法 (Reputation-based Discount Allocation)
*   贡献流量并不是获得满额奖励的唯一条件，**历史信誉库（Reputation, 0-100分）**决定了节点的真实收益转化率。
*   **收益折扣率公式**：`实际奖金 = 底薪 × (个人信誉分 / 100.0)`。
*   信誉受损的节点即使提供带宽，也会产生高额的**“惩戒没收损耗税”**，这在数学上证明了“积累信誉”比“一次性作恶”在长期博弈中具有更高的期望收益。

### 1.4 行为快照审计防御模型 (Behavioral Snapshot Auditing)
*   传统的结算模型存在“日切瞬时漏洞”：作恶用户在白天关闭分享疯狂下载，在半夜（结算前）突击打开分享以骗取“合作者”身份逃避惩罚。
*   系统采用了**快照级行为审计**。当流量发生消耗时，系统立刻抓取当前节点的分享状态开关。如果开关为 OFF，则打上不可洗白的违规标签（归入 `freerideGb` 案底）。结算时只需读取案底，彻底消灭了“突击伪装”作弊的空间。

## 2. 技术实现思路 (Implementation Ideas)

*   **轻量化全栈架构**：使用 Spring Boot + MyBatis-Plus 作为核心后端引擎，前端通过纯原生 HTML/JS + Bootstrap 5 + Thymeleaf 渲染，去除了繁重的框架依赖，使得 Demo 极其轻量。
*   **上帝视角 / 离散事件演算系统**：打破传统的“真实时间流逝”，改用“手动触发时间轴”（Trigger-based Time Simulation）。通过控制面板上的 `[时间流逝：结算今日配额]` 按钮，演示者可一键飞跃时间，直接触发次日凌晨的批量清算逻辑，极大地方便了现象展示。
*   **无状态的 P2P 资金流转模拟**：每次点击“消耗 1GB 流量”时，系统会在后端数据库实时拉取当前处于 `isSharing=true` 的节点，计算出节点总数，然后模拟 P2P 路由，将资金进行分割、打折、并派发给这些节点，完成了一次复杂的去中心化经济闭环结算。

## 3. Demo 演示系统功能特性 (Demo Features)

进入 Dashboard 主页，即可看到分为三个主要区域的控制大屏：

1.  **全局上帝控制台 (Global Control Panel)**
    *   显示当前的系统宏观经济汇率（消费费率、分享奖金池）。
    *   显示防作弊机制的安全申明。
    *   提供`[时间流逝：结算今日配额]`按键（核心驱动引擎）和`[重置数据]`功能。
2.  **三典型节点实时面板 (User Archetypes Dashboard)**
    系统预设了三种最具代表性的博弈论受试者：
    *   **老实合作者 (SHARER)**：常年开启分享，积分稳步上升，享受 100Mbps 极速。
    *   **利己搭便车者 (FREERIDER)**：自私自利关闭分享且大量消耗带宽，演示其受到红灯警告、信誉破产和 2Mbps 断网级限速的下场。
    *   **摇摆不定的普通人 (SWING)**：用于演示“从白嫖到被惩罚”，最后“洗心革面重新开启分享恢复网速”的完整赎罪链路。
3.  **实时操作防篡改日志框 (Action Logs)**
    *   像区块链区块浏览器一样，在底部实时打印出每一笔流量背后的资金调度、惩罚扣除微观过程，解释力强，方便汇报讲解。

## 4. 推荐的 Demo 演示操作剧本 (Operation Script)

为了在答辩/路演中达到最佳效果，推荐按照以下逻辑顺序操作页面：

**第一幕：初始状态与 P2P 供需模拟 (证明基础机制生效)**
1.  点击右上角 **“重置数据”**，确保所有人积分和网速(100Mbps)恢复初始状态。
2.  对 **利己搭便车者 (FREERIDER)** 连续点击两次 **“⏬ 消耗 1GB 流量”**。
3.  *讲解点*：此时观察下方“交互日志框”，可以看到 FREERIDER 被扣除了 12.00 分积分，同时这笔流量被路由交给了当前唯一在线的分享者 **老实合作者 (SHARER)**。SHARER 赚取了奖金，且因为他是高信誉，奖金是全额发放的。
4.  *注意*：此时可以看到 FREERIDER 的卡片上出现了红色的 `违规打标` 警告。

**第二幕：时间流逝与防作弊清算 (展示惩罚与降速机制)**
1.  *剧本冲突*：告诉评委/观众，这个 FREERIDER 很狡猾，他试图在今晚结算前开启分享来逃避惩罚。（点击 FREERIDER 的 **“🔄 切换分享开关”** 使其为 ON）。
2.  点击全局的 **“🕒 [时间流逝：结算今日配额]”**。
3.  *讲解点*：观察日志和卡片变化。系统虽然看到他在分享，但是快照审计查出了他的违规案底。不仅将他重罚（扣大分、扣声誉），且网速直接亮红灯变成 **⛔ 2 Mbps (已被限速)**。
4.  *讲解点*：与此同时，**老实合作者** 领取到了基础维持连通的红利；而什么都没干的 **摇摆人** 被扣除了少量的闲置税。

**第三幕：知错能改与动态恢复 (展示信誉系统博弈)**
1.  被限速的 FREERIDER 吸取了教训，决定以后必须开启分享。
2.  保持 FREERIDER 分享开关为 ON（如果刚才没切这次切过来），并且不要点消耗。
3.  对 **摇摆人 (SWING)** 点击 **“⏬ 消耗 1GB 流量”**，让他去消耗带宽。
4.  *讲解点*：在日志中可以清晰看到，刚才这1GB的需求，被路由派发给了两个分享者（老实人 + 戴罪立功的利己者）。但重点来了：由于 FREERIDER 的声誉分已经被上一轮惩罚扣得很低，系统根据“信誉折扣算法”，无情地没收了他的大部分工资作为损耗税，并在日志中单独标红。
5.  *最终收尾*：由此证明，系统实现了完整的激励闭环。作恶者即使重新合作，也必须经历漫长的“低薪打工”期才能修复声誉，以此彻底杜绝投机行为。
