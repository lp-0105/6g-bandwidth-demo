# 6G 去中心化带宽共享系统 - 开发者指南 🚀

本项目是一个基于 Spring Boot 开发的去中心化带宽共享生态系统 MVP。通过精巧的博弈论机制设计，直观展示了在 P2P 网络中如何通过经济激励和声誉系统惩治“自私节点”（搭便车者），鼓励节点“合作共享”，达到生态网络的帕累托最优。

---

## 🏗️ 1. 技术栈与架构 (Clean Architecture)

项目经历了深度的极简瘦身，废除了所有冗余代码和无效表结构，保留了最核心的最小解题闭环：

- **核心框架**: Spring Boot 3.2.3
- **语言**: Java 17
- **数据库**: H2 内存数据库（配置为 MySQL 模式）
- **ORM持久层**: MyBatis-Plus 3.5.5
- **前端渲染**: Thymeleaf + Bootstrap 5，异步 API 轮询
- **构建工具**: Maven

### 极简目录结构解析：
```text
src/main/
```

## 🧠 2. 底层博弈经济模型解析（论文核心创新点）

系统的核心逻辑全数收敛在 `UserBandwidthService.java` 中。没有任何冗余的批量模拟代码，一切结果均基于用户的真实点击演变而来。

### 2.1 全局精度升维（消除浮点漏洞）
系统内部将所有经济数值 **放大了 100 倍** 进行安全的高效整型(int)运算（如 12000 代表 120.00 分，并在前端渲染为两位小数）。这在底层数字经济系统开发中是防溢出的标准做法。

- `COST_PER_GB = 600`: 消耗 1GB 需要支付 6.00 分的基础油费。
- `REWARD_POOL_PER_GB = 500`: 每产生 1GB 流量，系统拿出 5.00 分作为全网分享者的基础奖金池。剩余的 1.00 分作为系统回收税被强制销毁，构成 **通缩型零和博弈**。

### 2.2 两大核心算法机制（最小博弈闭环）

#### A. 交易态：均摊承载与信誉折扣 (`consumeTraffic`)
- **流量均摊与由于声誉产生的沉没成本**：当产生 1GB 流量时，系统并非简单将任务塞给单人。而是拉取全网所有在线的分享者进行均摊。每个人拿到“平分底薪”后，按照其**信誉分折扣**（0~100）进行结算。信誉不满 100 分的节点，部分奖金将被系统作为**“惩戒税”直接没收销毁**（意味着有过不良记录的节点，即便浪子回头开启了共享，接单的转化率也会被打折）。
- **防作弊快照打标（Transaction Tagging）**：消费流量的瞬间，系统捕捉节点当下的开关状态。如果未开共享却索取带宽，该流量不会计入普通消耗，而是被死死烙上无法篡改的 `freerideGb`（违规案底）印记。

#### B. 结算态：零容忍秋后算账与双向激励 (`settleDaily`)
- **雷霆制裁机制（日切漏洞防御）**：日终结算时，系统不再轻信节点结算前一秒的临时开关状态。只要它存在 `freerideGb > 0` 的案底，即使伪装成开启分享，系统也必将其连根拔起：剥夺今日一切分红资格，处以 `8.00分/GB` 顶格罚款，扣除 20 声誉并 **无期降速至 2Mbps**！
- **连通性红利**：一直保持在线的分享者，哪怕今天全网没人下载，也能获得 10.00 分基础红利，用于填平挂机成本。
- **基建闲置税**：既不分享也不消耗的“潜水休眠节点”，会被系统抽收资产 1% 的闲置税。该机制不仅能将死号清零，更能在博弈中倒逼摇摆节点必须开机共享，才能跑赢通胀。

## 🔌 3. API 接口规范

前端面板采用原生 JavaScript fetch 每隔 2 秒自动向后端静默轮询，拉取上帝视角数据并渲染。

| 接口路径 | 请求方式 | 作用说明 |
|---------|---------|---------|
| `/` | GET | 渲染并返回上帝视觉监控主面板 (`index.html`) |
| `/api/users` | GET | 实时抽取全网 3 个节点当前状态参数的 JSON |
| `/api/action/consume` | POST | 强制指定用户消耗 1GB 带宽（触发瞬时快照与轮盘赌分配，检验其是否违规） |
| `/api/action/settle`  | POST | 管理员手动推演【日终结算】，验证秋后算账逻辑是否生效 |
| `/api/action/toggle-share` | POST | 切换指定节点的分享状态（配合结算，供演示漏洞防御机制）|
| `/api/action/reset` | POST | 环境快照回档，清除全员案底，积分与网速回归 `data.sql` 初始满血设定|

## 👩‍💻 4. 本地环境启停指南

1. **清理旧缓存**：如果在高强度调试时遇到数据灵异事件，在终端执行 `mvn clean` 清空历史 class 残留。
2. **极速启动**：终端键入 `mvn spring-boot:run` 即可唤醒 Spring Boot。
3. **前端热更新与调试**：得益于 Thymeleaf 缓存释放配置，如果你微调了 `index.html` 的文字或样式，无需重启庞大的后端服务。仅需在浏览器直接按 `F5` 刷新页面即可实时检阅效果！
